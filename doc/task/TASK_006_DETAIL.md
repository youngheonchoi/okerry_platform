# TASK 006. SSO 회원가입 및 DB 기반 로그인 구현


## 목적

회원가입 화면에서 입력받은 SSO 사용자 정보를 안전하게 DB에 저장하고, 저장된 이메일과 비밀번호 인증 정보로 Spring Security 로그인을 처리한다.


## 선행 작업

* TASK 005. SSO 사용자 저장 기반 구현
* `/doc/architecture/DATABASE.md`에 정의된 사용자 및 권한 테이블과 `AUTH_USER` 초기 데이터 준비


## 구현 범위

### 회원가입

* 회원가입 폼의 이름, 이메일, 비밀번호, 비밀번호 확인 값을 서버에서 검증한다.
* 이메일 형식, 필수 입력값, 길이 제한, 비밀번호 정책, 비밀번호 확인 일치 여부를 검증한다.
* 이메일은 비교 전에 정규화하고 DB의 유일성 제약 조건과 함께 중복 가입을 방지한다.
* 비밀번호 원문은 저장하거나 로그에 남기지 않고 TASK 005의 비밀번호 해시 기능을 사용한다.
* `auth_users`, `auth_user_credentials`, `auth_user_roles` 저장을 하나의 트랜잭션으로 처리한다.
* 회원가입 사용자에게 DB에 준비된 `AUTH_USER` 권한을 연결한다.
* `AUTH_USER` 권한이 없으면 임의로 생성하지 않고 회원가입을 실패 처리한다.
* 이메일 인증 기능을 구현하기 전까지 가입 계정은 `ACTIVE`, `email_verified=false`로 저장한다.
* 회원가입 성공 시 로그인 화면으로 이동하고, 실패 시 입력 오류를 회원가입 화면에 안전하게 표시한다.

### 로그인

* 이메일을 로그인 ID로 사용해 사용자, 인증 정보, 권한을 DB에서 조회한다.
* Spring Security의 인증 과정에 DB 기반 사용자 조회와 비밀번호 검증을 연결한다.
* `ACTIVE` 상태의 사용자만 로그인할 수 있도록 계정 상태를 검증한다.
* `locked_until`이 현재 시각 이후인 계정은 로그인할 수 없도록 검증한다.
* 로그인 성공 시 `last_login_at`을 갱신하고 서비스 목록 화면으로 이동한다.
* 로그인 실패 시 이메일 존재 여부나 계정 상태를 추론하기 어려운 공통 실패 메시지를 사용한다.
* 로그아웃 후 인증 세션이 무효화되고 로그인 화면으로 이동하는 기존 흐름을 유지한다.

### 보안 및 검증

* 비밀번호, 비밀번호 해시, 세션 식별자 등 인증 비밀정보를 로그에 기록하지 않는다.
* 회원가입의 상태 변경 요청에는 CSRF 보호를 유지한다.
* 중복 요청과 DB 제약 조건 위반을 내부 예외 그대로 노출하지 않고 사용자용 오류로 변환한다.
* 회원가입 트랜잭션 실패 시 사용자, 인증 정보, 권한 연결이 일부만 저장되지 않도록 한다.
* 주요 성공 및 실패 흐름을 자동 테스트로 검증한다.
